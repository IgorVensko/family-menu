# Промпт для Claude Code — доработка приложения "Семейное меню" (v2)

Контекст: приложение уже существует (app.js, index.html, menu.json, style.css), задеплоено на GitHub Pages.
Нужно доработать логику под новую структуру данных (см. файл menu-week2.json в этом репозитории) — не переписывать с нуля, а расширить существующий функционал.

## Что изменилось в данных

1. **Обед может быть общим на 2 дня.** В menu-week2.json появилось поле верхнего уровня `lunchGroups` — массив групп, каждая группа содержит `id`, `days` (список из 2 дней), `type: "soup_2days"` и `options` (3 варианта супа с ингредиентами и БЖУ на порцию). У каждого дня в `days`, который относится к такой группе, есть поле `lunchGroupRef`, ссылающееся на `id` группы, ВМЕСТО собственного массива `meals.lunch`.

2. **Ужин может быть "заказом еды".** Вместо массива из 3 вариантов, `meals.dinner` для дня может быть объектом `{ "type": "order_in", "note": "..." }` — это значит готовка не нужна, ужин не выбирается из вариантов.

3. Появилось поле `weekend` — блок с воскресеньем/субботой без выбора вариантов (просто текстовые описания), можно вывести как отдельный неинтерактивный блок в конце недели.

## Что нужно доработать в UI

1. **Рендер обеда**: если у дня есть `lunchGroupRef` — искать группу в `lunchGroups` по id, показывать её `options` как обычные 3 карточки выбора, НО:
   - выбор синхронизируется между обоими днями группы (выбрал суп в понедельник — во вторник карточка уже отмечена тем же выбором, показывается пометка "тот же суп, что и вчера")
      - в списке покупок ингредиенты супа считаются ОДИН раз (не дублировать на оба дня)

      2. **Рендер ужина "заказ еды"**: если `meals.dinner.type === "order_in"` — вместо 3 карточек показать один информационный блок с текстом из `note`, без выбора и без добавления в список покупок

      3. **Список покупок**: обновить логику суммирования ингредиентов с учётом двух новых типов данных (общий суп считается 1 раз, order_in не считается вообще)

      4. Блок `weekend` — вывести под основной неделей как простой информационный список (суббота/воскресенье), без интерактивности

      ## Технические детали

      - Сохранить существующий стиль кода и подход к данным (JSON + localStorage), не менять архитектуру
      - Название файла с данными для новой недели: `menu-week2.json` (уже в репозитории) — сделать выбор недели (можно временно захардкодить путь к файлу, полноценный выбор недель — отдельная задача, не в этом промпте)
      - Мобильная адаптивность — как в текущей версии, не терять

      Начни с рефакторинга функции загрузки/рендера меню под новую структуру данных, затем логику списка покупок, затем визуальные пометки (общий суп / заказ еды).
